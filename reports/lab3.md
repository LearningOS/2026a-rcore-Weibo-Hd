## 一、实现的功能

这一章分两块。

一是把上一章的 `get_time`、`mmap`、`munmap` 搬过来。ch5 换成了真正的进程模型，每个进程有独立的 PCB、pid 和内核栈，地址空间挂在 PCB 内部，所以取 token、取 `memory_set` 的方式都得跟着改。

二是这章的重点。实现了 `spawn`：直接用 elf 建一份新的地址空间，把新进程挂到当前进程的 `children` 下，和 fork 那种复制父进程内存的做法不是一回事。另外把原来的 FIFO 调度器换成了 stride 调度：每个进程记 `priority`、`pass`、`stride`，每次挑 `stride` 最小的运行，跑完把自己的 `pass` 累加上去。`set_priority` 负责改优先级并重算 `pass`。

## 二、简答作业

### 2.1 8 位 stride 下会不会轮到 p1

不会，实际又轮到了 p2。

`p2` 跑完一个时间片后 `stride = 250 + 10 = 260`，8 位无符号存不下，回绕成 4。这时候 `p2.stride = 4`，比 `p1` 的 255 小得多，调度器认为 p2 还欠着时间，于是继续选它。这就是 stride 算法的“反转”。

### 2.2 为什么要求优先级 ≥ 2

`pass = BigStride / priority`，所以 `priority >= 2` 等价于 `pass <= BigStride / 2 = B/2`。

下面用归纳的方式说个大概（不追求严格）。

假设某一时刻所有进程的 stride 都落在 `[min, max]` 里，且 `max - min <= B/2`。下一次被选中的一定是最小的那个，假设叫 `s`，给它加上 `pass = p`，新值 `s + p`。分两种情况：

- `s + p <= max`：最大值没变。其它进程的 stride 只增不减，所以新的最小值不会比原来的 `s` 更小；而 `s` 本身不小于 `max - B/2`。于是新的跨度仍然不超过 `B/2`。
- `s + p > max`：它成了新的最大值。它比原来的 `max` 最多大 `p - (max - s)`，而 `max - s >= 0`，所以这个超出量不超过 `p`；新的最小值至少是原来的 `s`。两者相减不超过 `p <= B/2`。

关键就在最后这一步：只有 `p <= B/2` 才兜得住。如果优先级取 1，`pass` 就等于 `B`，加一次就能让跨度翻倍，比较器再怎么设计也分不清谁在前谁在后了。

### 2.3 溢出情况下的比较器

8 位下 125 和 255 谁大，不能直接比数值，要看它们相距多远——差超过半圈就说明已经绕过一轮，顺序要反过来。所以本质上是比**有符号的差值**：

```rust
impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        let diff = self.0.wrapping_sub(other.0) as i64;
        Some(diff.cmp(&0))
    }
}
```

`wrapping_sub` 把差值限制在一个周期之内，转成有符号数之后，负数说明 `self` 落在 `other` 后面，正数说明在前面。

拿题目给的两个例子验证：`125 - 255 = -130`，按 8 位回绕成 `+126`，是正数，所以 `125 > 255`，`(125 < 255) == false`；`129 - 255 = -126`，是负数，所以 `129 < 255`，`(129 < 255) == true`。和提示一致。

这个比较器能成立的前提是：任意两个 stride 的差距不超过半个周期。2.2 的结论恰好保证了这一点，所以两者是配套的。

## 四、其他

调度器没有用优先队列，就是线性扫一遍找最小的 `stride`。测例规模太小，`VecDeque` 里最多几十个进程，为这个引入 `BinaryHeap` 加上自定义比较器反而更容易出错——真要做优化，等进程数量上千了再说。

实现时踩了一个和算法无关的坑：为了在 syscall 层直接调 `PageTable::from_token`，我把 `mm/mod.rs` 里的导入改成了 `pub use`。结果 `PTEFlags` 和 `PageTable` 变成对外公开的符号，内核开着 `#![deny(missing_docs)]`，模板里那些 bitflags 常量和 `map`/`unmap` 都没写文档，编译直接失败。

有意思的是测例仍然报了 `2/15`——因为 15 个检查点里恰好有两个是“**不应该**出现某个字符串”，内核没跑起来、输出为空，这两项反而满足了。空输出也能“通过”检查，这个设计如果没有那两项反向检查，编译失败会被误判成部分得分。

最后改成了在 `mm` 里封装一个 `user_write_u8`，让 `PageTable` 保持私有。回头想这样其实更合理：往用户地址写字节本来就是内存管理该负责的事，syscall 层不该自己去拼页表。
